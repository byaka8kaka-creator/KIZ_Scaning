# КИЗ — расширение для Chromium-Gost

Расширение Manifest V3 загружает КИЗ из Excel и получает `expirationDate`, `gtin`, `cis` из True API Честного знака. Сервер для работы не нужен.

## Установка

1. Скачайте и распакуйте `kiz-extension.zip`. Либо соберите проект командами ниже.
2. В Chromium-Gost откройте `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение**.
3. Выберите папку с `manifest.json`: папку распакованного архива либо `dist/` после сборки.
4. Нажмите значок «КИЗ — сроки годности». Откроется отдельная вкладка.

Для подписи на компьютере должны работать КриптоПро CSP, КриптоПро ЭЦП Browser plug-in и его браузерное расширение. Нужны действующий сертификат, доступ к закрытому ключу и права пользователя в Честном знаке. Наше расширение не устанавливает КриптоПро и не получает закрытый ключ.

## Авторизация

1. Нажмите **Авторизоваться через КриптоПро**. Расширение отправит GET без тела на `https://markirovka.crpt.ru/api/v3/true-api/auth/key` и откроет указанную страницу КриптоПро.
2. На ней появится дополнительная панель «КИЗ: подпись запроса авторизации». Выберите действующий сертификат, например **Труфанова Лариса Анатольевна**. Сертификат не выбирается автоматически.
3. Нажмите **Подставить данные для подписи** на панели расширения. Проверьте, что поле страницы «Данные для подписи» содержит данные запроса, а не `Hello World`.
4. Оставьте флажки **Отделенная подпись** и **Проверять подписанта** снятыми, как на предоставленных скриншотах. Нажмите штатную кнопку **Подписать**. Подтвердите операцию КриптоПро, если потребуется.
5. После сообщения об успешной подписи нажмите **Передать готовую подпись в КИЗ**. Расширение отправит POST `/auth/simpleSignIn` с JSON `{"uuid":"…","data":"подпись Base64"}`.
6. Вернитесь во вкладку КИЗ. Там отобразится срок авторизации.

Если элементы страницы изменились и автоматическая подстановка/чтение не работает, скопируйте данные из панели в поле страницы вручную. Полученную подпись вставьте в **Вставить подпись вручную** на вкладке КИЗ и нажмите **Отправить подпись**. Подписывайте только текущие данные, не `Hello World`.

Токен хранится локально в профиле браузера и используется **10 часов** с момента начала успешного запроса входа, в том числе после перезапуска браузера. При наличии действующего токена новый `auth/key` не запрашивается. Ответ `401` сбрасывает токен; для продолжения нужно повторно авторизоваться. Ошибки сети, `403`, `429`, `5xx` токен не сбрасывают. Автоматических повторов авторизации и подписания нет. Новый запрос подписи локально действует 5 минут; после этого снова нажмите кнопку авторизации. Это ограничение расширения, а не заявленный срок жизни uuid у API.

Токен не синхронизируется через Chrome Sync, не выводится на экран и не передаётся странице КриптоПро. Он хранится в `chrome.storage.local` с ограничением доступа доверенными контекстами, если браузер поддерживает `setAccessLevel`. В Chromium-Gost без этого API используется стандартный режим хранения браузера. Удаление расширения/его данных удаляет токен. Не передавайте профиль браузера другим людям.

## Excel и получение результатов

1. Выберите `.xls` или `.xlsx` (до 20 МБ).
2. Выберите лист и столбец с КИЗ. По умолчанию первая строка считается заголовком; снимите флажок, если заголовка нет.
3. КИЗ должны быть **текстовыми ячейками**. Числовые ячейки отклоняются: Excel мог уже потерять ведущие нули или точность. Простая смена формата после потери точности не восстановит код.
4. Расширение удаляет пробелы по краям, берёт первые **24 символа** каждого непустого КИЗ и объединяет дубликаты с учётом регистра. Короткие и числовые значения отображаются как ошибки импорта и не отправляются. Можно обработать остальные корректные строки.
5. Нажмите **Получить данные**. POST `/cises/info` получает JSON-массив строк КИЗ и заголовок `Authorization: Bearer <token>`. Размер пакета — до 100 КИЗ, пакеты идут последовательно.
6. Результат содержит `cis`, `gtin`, `expirationDate`, дополнительный столбец `error`. Даты отображаются как `ДД.ММ.ГГГГ` без времени. В Excel используются ячейки даты с форматом `dd.mm.yyyy`, в JSON — строки `ДД.ММ.ГГГГ`. Отсутствующие данные не придумываются. Поддерживаются записи с `cisInfo` и плоские записи; ошибки с `requestedCis` связываются с исходным КИЗ.
7. Скачайте Excel или JSON. В таблице отображаются первые 1000 строк, в выгрузке — все полученные результаты. Если запрос завершился ошибкой, уже полученные результаты остаются доступны. Повторное нажатие **Получить данные** начинает обработку заново.

Остановка происходит после текущего пакета; закрытие вкладки останавливает очередь. Файл целиком не отправляется: на API уходят только выбранные 24-символьные КИЗ. Данные файла/результатов остаются в памяти вкладки. Исходный запрос временно хранится в памяти сеанса расширения до успешного входа (если session storage отсутствует — в локальном хранилище, с проверкой срока 5 минут); токен — локально на 10 часов. Никакой аналитики или стороннего сервера нет. Библиотека Excel включена в сборку, удалённого исполняемого кода в расширении нет.

## Разработка

Требуются Node.js 24 и npm. Используйте существующий checkout; отдельный Git worktree не требуется.

```sh
npm ci --ignore-scripts
npm run check
```

Сборка находится в `dist/`. После изменений повторите `npm run build` и нажмите «Обновить» на карточке расширения в браузере. `dist/` и `node_modules/` не включены в Git. Сборка включает лицензию Apache-2.0 используемой библиотеки `@e965/xlsx`.

Проверки:

- `npm test`: 8 модульных тестов — срок токена, HTTP-контракты, ошибки, настоящие XLS/XLSX, разбор ответов.
- `npm run test:ui`: интерфейс в настоящем Chromium + реальный фоновый модуль с имитацией Chrome API и HTTP. Проверяет авторизацию, повторное использование/истечение токена, импорт обоих форматов, выгрузку Excel, поведение при `403`/`401`, валидацию источника сообщения и мост DOM КриптоПро на тестовой странице. По умолчанию используется `/usr/lib/chromium/chromium`; другой путь можно задать через `CHROMIUM_PATH`.
- `npm run test:e2e`: отдельный тест загрузки самого MV3-расширения и взаимодействия вкладок с тестовыми ответами API. Требует Chromium с разрешёнными распакованными расширениями и CDP `Extensions.loadUnpacked`.

## Что проверено и что требует проверки на рабочем компьютере

Модульные тесты и браузерный тест интерфейса с имитацией внешних систем выполнены. `npm audit --omit=dev` не выявил известных уязвимостей на момент реализации.

В облачной среде системный Chromium запрещает загрузку распакованных расширений политикой администратора. Поэтому тест установки MV3 здесь не прошёл; он не считается пройденным. Загрузка публичной страницы КриптоПро из среды вернула HTTP 403. Её текущую разметку не удалось подтвердить; автоматический мост использует `DataToSignTxtBox` и `SignatureTxtBox`, ручной сценарий предусмотрен независимо от этих идентификаторов.

Реальные запросы True API, настоящая ГОСТ-подпись, сертификат пользователя и работа плагина в Chromium-Gost **не проверены**. Для приёмки установите расширение в Chromium-Gost, пройдите авторизацию своим сертификатом, обработайте несколько известных КИЗ и сверьте даты/GTIN. Повторная обработка до истечения токена не должна открывать КриптоПро. Возможные ограничения доступа True API зависят от прав владельца сертификата и сети рабочего компьютера.

## Версия 1.0.1: совместимость и журнал

Исправлено падение service worker `setAccessLevel is not a function`: наличие необязательных API проверяется; ошибки настройки доступа не блокируют кнопку запуска. При отсутствии `storage.session` временный запрос подписи хранится в `storage.local` и проверяется на истечение срока.

В разделе **Диагностика** нажмите **Скачать журнал** и приложите полученный `kiz-log-….json` к описанию ошибки. Можно очистить журнал отдельной кнопкой. Журнал сохраняется после закрытия вкладки и перезапуска браузера, содержит последние 500 событий. Фиксируются запуск worker и вкладки, возможности браузера, этапы КриптоПро, операции авторизации/импорта/экспорта, пути API, HTTP-статусы, длительность и типы ошибок. В выгрузке также есть версия расширения и User-Agent браузера. Тела запросов/ответов, uuid, данные для подписи, подписи, токены, имена файлов, сертификаты и КИЗ не записываются. Экспорт читает журнал непосредственно из хранилища, даже если фоновый модуль перестал отвечать, но вкладка приложения уже открыта.

Обновление: замените файлы старой папки расширения содержимым нового архива и нажмите **Обновить** на карточке в `chrome://extensions`. Закройте старую вкладку приложения и откройте новую значком расширения. При сборке из Git используйте `npm ci --ignore-scripts && npm run build` и загрузите `dist/`. Старую ошибку на странице расширений можно удалить после обновления. Если вкладка всё ещё не открывается, откройте «Сведения → Проверить представления → service worker» и сохраните новую ошибку; при полном отказе регистрации worker приложение не может само записать эту ошибку.

## Версия 1.0.2: чтение Excel

Библиотека Excel и её лицензия теперь включены в `extension/vendor/` и отслеживаются Git. Поэтому папка `extension/` из GitHub тоже пригодна для загрузки как распакованное расширение без предварительной сборки. Устанавливайте папку целиком; перенос только HTML/JS без `vendor/` приведёт к отсутствию библиотеки. Установочный ZIP содержит всё необходимое в корне.

Если библиотека отсутствует, приложение сразу показывает понятную ошибку и блокирует загрузку файла. Пустой или неудачный импорт больше не отображается как готовый к запросу. Лист и столбец явно выбираются после заполнения списков. Если первая ячейка начинается с GS1 `01` + 14 цифр + `21`, флажок заголовка автоматически снимается; его можно изменить вручную. В диагностике импорта теперь есть количества листов, строк, столбцов и ошибок, выбранный индекс столбца и признак заголовка, без содержимого ячеек.

Приложенный пользователем файл проверен локально: 8 уникальных текстовых КИЗ без заголовка, ошибок импорта нет. Файл пользователя не включён в репозиторий или архив. Проверен импорт через интерфейс из папки `extension/`, доступность кнопки запроса и обработка отсутствующей библиотеки. Для повторения проверки с локальным файлом можно задать `KIZ_TEST_WORKBOOK=/путь/к/файлу.xlsx` (тест ожидает 8 корректных КИЗ), `KIZ_TEST_SOURCE=extension` и выполнить `npm run test:ui`.

## Версия 1.0.3: ручной ввод и сканер

В разделе **2. Загрузка КИЗ** нажмите **Сканировать**. В открывшемся окне введите КИЗ вручную или используйте сканер, работающий как клавиатура с Enter в конце. **Enter** или кнопка **Сохранить** добавляют код в список текущей вкладки, очищают поле и возвращают фокус для следующего сканирования. При вводе менее 24 символов после удаления пробелов по краям появляется сообщение **«Отсканирован не КИЗ»**, значение не сохраняется. Для длинных кодов используются первые 24 символа. Дубликаты, включая совпадения с Excel, пропускаются.

Нажмите **Готово** или Escape, затем **Получить данные** для обработки всех добавленных КИЗ. Файл Excel для ручного ввода не требуется. Ручные КИЗ сохраняются при загрузке другого файла и выборе листа/столбца. Кнопка **Очистить ручной ввод** удаляет только ручные коды, сохраняя коды из файла. Изменение списка сбрасывает прежние результаты: повторите запрос для нового списка. Список хранится в памяти вкладки до её закрытия или перезагрузки. В журнал попадают только события и счётчик ручного ввода, без значений кодов.

Проверено в браузерном тесте: отклонение 23 символов, сохранение 24 символов, обрезка длинного кода, повторы, запрос без Excel, объединение с файлом, очистка ручного ввода и закрытие окна через Escape.

## Версия 1.0.4: срок годности без времени

`expirationDate` вида `2027-10-05T00:00:00.000Z` преобразуется в `05.10.2027` в таблице и JSON. В Excel сохраняется числовая дата с форматом `dd.mm.yyyy`, а не текст или дата со временем. Используется календарный день из ответа API без пересчёта часового пояса. Пустые даты остаются пустыми, нераспознанные значения сохраняются как есть. Проверены таблица, JSON и тип/формат ячейки в скачанном Excel.

## Версия 1.0.5: полный код и русская раскладка

В третьем шаге, Excel и JSON добавлен столбец `cis_full`: полный введённый код после исправления русской раскладки. В API, как и раньше, отправляется `cis` — первые 24 символа исправленного кода. Исправление применяется к ручному вводу и Excel, учитывает регистр и Shift для знаков. Латинские символы и служебные разделители, включая GS (U+001D), не изменяются. Пробелы по краям по-прежнему удаляются.

Пример: `0104650096358972215чоПФт<GS>931СКн` сохраняется как `0104650096358972215xjGAn<GS>931CRy`, в API отправляется `0104650096358972215xjGAn`. Здесь `<GS>` обозначает настоящий служебный символ, а не текстовую замену; в JSON он записывается стандартным экранированием `\u001d`.

Точные повторы полных кодов пропускаются. Разные полные коды с одинаковым `cis` сохраняются отдельными строками результатов с одинаковыми данными API. Сам запрос для этого `cis` выполняется один раз. Счётчик обработки показывает количество уникальных `cis`, поэтому строк выгрузки может быть больше. Если запрос для кода не успел выполниться, его результат не попадёт в частичную выгрузку; список ввода остаётся в текущей вкладке. Полные коды в журнал диагностики не записываются.

Проверены пример пользователя, регистр, знаки Shift, служебный разделитель, импорт, полный код в таблице и экспорт Excel/JSON. Даты в выгрузке остаются ячейками даты без времени.
